# pgsql-hackers digest — Feb 21, 2026

1. **Shutdown indefinitely stuck due to unflushed FPI_FOR_HINT record** — Anthonin Bonnefoy reports that shutdown can hang indefinitely when a logical replication walsender tries to read an unflushed FPI_FOR_HINT record left by a killed transaction, proposing a fix that flushes all records before signaling walsenders to stop. https://www.postgresql.org/message-id/CAO6_Xqo3co3BuUVEVzkaBVw9LidBgeeQ_2hfxeLMQcXwovB3GQ@mail.gmail.com

2. **Standby follows wrong timeline after switchover** — Andrey Borodin reports that XLogFileReadAnyTLI can silently apply divergent WAL from the wrong timeline during archive recovery, causing a standby to remain on an old primary's timeline after a planned HA switchover instead of following the promoted primary's new timeline. https://www.postgresql.org/message-id/85386EF6-16B7-4D62-86BE-526A10F93825@yandex-team.ru

3. **SLRU error messages need better 64-bit formatting** — Maxim Orlov proposes improving SLRU error messages to properly report 64-bit transaction IDs and multixid offsets; Heikki Linnakangas suggests using SLRU-specific callbacks instead of the generic "%u:%u" format since it's misleading for contexts like pg_async that use InvalidTransactionId. https://www.postgresql.org/message-id/5b4e458d-94f1-4ca3-ab72-aae8328e038d@iki.fi

4. **Interrupts mechanism gets "attention bitmask"** — Heikki Linnakangas adds an attention bitmask where backends advertise which interrupts they're currently interested in, allowing SendInterrupt() to avoid spurious wakeups and unnecessary ProcessInterrupts() calls by checking the recipient's mask before sending. https://www.postgresql.org/message-id/d446c315-5af9-4537-9cd9-605fd1b58412@iki.fi

5. **Make copyObject work in C++** — Jelte Fennema-Nio updates the patch to add a configure test for C++ typeof support and defines typeof as decltype where needed, also improving unconstify/unvolatize by using StaticAssertVariableIsOfTypeMacro instead of custom assertions. https://www.postgresql.org/message-id/DGJP03W74JEL.3QCBCVYISLNQ6@jeltef.nl

6. **Adding locks statistics needs use case justification** — Andres Freund pushes back on continued expansion of lock statistics, asking for clear use cases before implementing more counters and warning that the split between waits/timed_waits/wait_time wastes resources and confuses users without demonstrable benefit. https://www.postgresql.org/message-id/isi5wszczhusgjetxwe6khxa5mbm5jms3msmbhwl73jktxw7ic@3mympoumua76

7. **Release notes for February 26 re-releases** — Tom Lane posts first-draft release notes for PostgreSQL 18.3, documenting fixes for the substring() encoding error and standby transaction status regressions that triggered the out-of-cycle release. https://www.postgresql.org/message-id/2946121.1771619586@sss.pgh.pa.us

8. **ECDH support causes unnecessary roundtrips fixed** — Daniel Gustafsson applies additional test suite adjustments for FIPS environments after the initial ECDH fix, catching test failures in suites beyond the main ssl tests. https://www.postgresql.org/message-id/7BEC1173-B919-4BEC-AADB-D998B8AD8B90@yesql.se

9. **Automatic sequence replication updates** — Ajin Cherian posts v5 of the sequence sync patch addressing review feedback, fixing stale comments about lock acquisition and handling unexpected relstates properly. https://www.postgresql.org/message-id/CAFPTHDZiWYXoKoo4VcBYNH9a=gxDZhfkcBeXt5w6cLw4_ysyKw@mail.gmail.com

10. **CPU feature detection centralization progresses** — Zsolt Parragi reviews patches 1-3 favorably aside from commit messages and notes a typo in "Are ZMM registeres enabled?" comment. https://www.postgresql.org/message-id/CAN4CZFNWZwk3vv3_cD=Z9DonWsSuwX18mRhc10Ktu3vt3gtaYg@mail.gmail.com
