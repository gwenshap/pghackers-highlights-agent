# pgsql-hackers digest — Mar 2, 2026

1. **Unlogged table fake LSNs passed to XLogNeedsFlush in GetVictimBuffer** — Andres Freund and Melanie Plageman fix a bug where GetVictimBuffer() reads LSNs from unlogged table buffers and passes them to XLogNeedsFlush() without checking BM_PERMANENT; currently harmless since only bulkread strategies call StrategyRejectBuffer(), but could break if XLogNeedsFlush() gains LSN range assertions or tries to wake walwriter with bogus values. https://www.postgresql.org/message-id/tsoi4ahsvxl7ln3ltmkhi4wn6p5b36uiokll5j2mzsfhpl6i7w@brc33vsxcdum

2. **estimate_hash_bucket_stats rel->rows fix committed, avgfreq investigation continues** — Tom Lane commits the s/rel->rows/rel->tuples/ fix which reverted all plan changes from bd3e3e9e5 except one involving zero mcv_freq; continues investigating Joel Jacobson's proposed avgfreq calculation change separately, noting that for unique columns the result should be bounded by 1/ndistinct, not 1/(rel->tuples). https://www.postgresql.org/message-id/438794.1772399542@sss.pgh.pa.us

3. **PLpgSQL FOREACH IN JSON ARRAY updated with array variable support** — Pavel Stehule updates the patch to support assignment to plpgsql array variables from JSON arrays, adds code cleaning and more regression tests to the proof-of-concept that's already 3-4x faster than FOR IN SELECT FROM json_array_elements(). https://www.postgresql.org/message-id/CAFj8pRCBUtakcgBF2uZ-+2rq9Kzw-p0V1i6B73gfiVjwKct3AQ@mail.gmail.com

4. **RI trigger batching enables 3.2x speedup with I/O prefetching** — Tomas Vondra reports that Amit Langote's RI trigger batching gives only 1.08x on I/O-bound workloads alone (161s→149s) but combined with index prefetching yields 3.2x (→51s) because batching provides a window of upcoming probes for prefetch machinery; wonders if similar batching could help index inserts and shares additional benchmarks on data distribution sensitivity and batch size tuning. https://www.postgresql.org/message-id/43b56e3b-80d6-4a45-a313-cb1caa587b22@vondra.me

5. **RegisterExtensionExplainOption sizeof bug causes crash after 8 options** — Joel Jacobson discovers that explain_state.c used sizeof(char *) instead of sizeof(ExplainExtensionOption) in allocations, causing crashes when extensions register more than 8 EXPLAIN options; provides test extension demonstrating the bug where EXPLAIN (test_explain_opt9) terminates the server. https://www.postgresql.org/message-id/2a4bd2f5-2a2f-409f-8ac7-110dd3fad4fc@app.fastmail.com

6. **Solaris/Illumos semaphore exhaustion fixed with UNNAMED_POSIX** — Tom Lane proposes adding PREFERRED_SEMAPHORES=UNNAMED_POSIX for Solaris/OpenIndiana after BF member icarus hits "could not create semaphores: No space left on device" during parallel tests, since unnamed POSIX semaphores work fine and avoid needing to increase SEMMNI/SEMMNS; also notes ps_status.c doesn't work on Solaris (all processes show postmaster's command line). https://www.postgresql.org/message-id/470305.1772417108@sss.pgh.pa.us

7. **Shutdown hang fix revised to minimize backport risk** — Anthonin Bonnefoy updates the FPI_FOR_HINT shutdown hang patch after Fujii Masao suggests calling XLogSetAsyncXactLSN() in ShutdownXLOG() instead of RecordTransactionAbort() to minimize changes for backporting, though the RecordTransactionAbort approach better handles backlog of records from selects pruning many pages; adds optimization to skip spinlocks when XactLastRecEnd is 0. https://www.postgresql.org/message-id/CAO6_Xqp%2BADb6KZVWLMALu3xmwVUEO8S1EiCnp38mG6BrHrEnuA@mail.gmail.com

8. **REPACK memory leak and SHM_MQ_DETACHED handling fixed** — Antonin Houska addresses Mihail Nikalayeu's findings by adding a per-change memory context to fix attrs/isnull array leaks, adding rd_pkindex fallback logic to rebuild_relation_finish_concurrent(), and clarifying that ProcessRepackMessages() doesn't need to check SHM_MQ_DETACHED because RepackWorkerShutdown() sends error messages via pq_redirect_to_shm_mq() before detaching. https://www.postgresql.org/message-id/67772.1772462341@localhost

9. **Publication partition detach/attach doesn't auto-refresh replication** — Nisha Moond reviews the EXCEPT TABLE publication patch and finds issues including testcase bug where $pubviaroot uses argument count instead of value causing both test runs to behave identically, and errmsg() calls with semicolons instead of commas after errdetail(). https://www.postgresql.org/message-id/CALDaNm32g7c323M4mgZ5Wn8sbYp_%3DuQ6G_u0f9qfBCzuHP8jgQ@mail.gmail.com

10. **pd_prune_xid clearing when setting PD_ALL_VISIBLE debated** — Melanie Plageman proposes clearing pd_prune_xid whenever PD_ALL_VISIBLE is set to avoid confusing cases where all-visible pages retain prune xids, arguing the next delete/update will set it again anyway; alternatively suggests WAL-logging pd_prune_xid in xl_heap_prune records to synchronize primary and standby values. https://www.postgresql.org/message-id/gwdfoam2qcdx3izhuiwypo4bnewddcxhir2nnyv4vihihu3i5j@4u2ybdwbhzqr
