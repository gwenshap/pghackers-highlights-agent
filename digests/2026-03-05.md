# pgsql-hackers digest — Mar 5, 2026

1. **DSA pagemap out-of-bounds bug in make_new_segment odd-sized path** — Paul Bunn identifies a critical bug where make_new_segment()'s Path 2 (odd-sized segments) allocates pagemap with `usable_pages` entries but FreePageManager hands out pages with indices from `metadata_pages` to `metadata_pages + usable_pages - 1`, causing out-of-bounds access when `metadata_pages >= 1`; bug caused parallel hash join crashes on Postgres 15 with workers computing pageno 196993 beyond pagemap's 196609 entries. https://www.postgresql.org/message-id/044401dcabac$fe432490$fac96db0$@icloud.com

2. **pg_combinebackup produces incorrect VM fork size after truncation** — Amul Sul reports that when a relation spanning multiple segments (>1GB) is truncated down to a single segment via VACUUM, the SMGR_TRUNCATE_ALL WAL record causes pg_combinebackup to reconstruct the Visibility Map fork with an incorrect "insanely high" size equal to the main fork; provides reproducer showing WAL summarizer may be mixing up information between relation forks. https://www.postgresql.org/message-id/CAAJ_b97PqG89hvPNJ8cGwmk94gJ9KOf_pLsowUyQGZgJY32o9g@mail.gmail.com

3. **Shutdown hang fix simplified to XLogFlush in walsender** — Anthonin Bonnefoy updates the FPI_FOR_HINT shutdown hang patch to call XLogFlush(GetXLogInsertRecPtr()) instead of XLogBackgroundFlush() during walsender shutdown, a minimal fix that only changes shutdown behavior; Fujii Masao plans to commit and backpatch barring objections. https://www.postgresql.org/message-id/CAO6_Xqq1h6kggb1o206rgouPS0H5jnjahzZ0We-9ggnBjB2JsA@mail.gmail.com

4. **intarray _int_matchsel crash on invalid query_int input** — Eugeny Goryachev finds that _int_matchsel() assumes the right-hand argument is valid query_int and can dereference invalid pointers if a malformed value is passed (e.g., via implicit cast from user-defined type created WITHOUT FUNCTION); patch adds minimal size check before dereferencing, raising ERRCODE_DATATYPE_MISMATCH instead of crashing. https://www.postgresql.org/message-id/CABg3sZrVkXuYx5qO4Bw4AihzqWnB4ukqXZpPep7o0-skNNWgLw@mail.gmail.com

5. **UBSAN crash in EventTriggerCollectAlterTSConfig with NULL memcpy fixed** — Álvaro Herrera commits fix for bug where DROP MAPPING unconditionally calls EventTriggerCollectAlterTSConfig() with NULL dictIds and ndicts=0, reaching `memcpy(command->d.atscfg.dictIds, NULL, 0)` which triggers SIGABRT under -fsanitize=undefined; bug has been latent since b488c580aef (9.5) because function returns early without active event trigger. https://www.postgresql.org/message-id/CA+HEvJB5rcUzi+DBf7+ckb=rYoyTEjX0MM3FxKPUErmJUv+sEQ@mail.gmail.com

6. **import_pg_statistic() uses pfree() instead of heap_freetuple()** — Yonghao Lee discovers that import_pg_statistic() calls pfree(pgstup) after heap_form_tuple(), which only frees the HeapTupleData structure itself but leaves the underlying t_data unfreed; should use heap_freetuple(pgstup) to properly free both the structure and the nested tuple data. https://www.postgresql.org/message-id/tencent_CA1315EE8FB9C62F742C71E95FAD72214205@qq.com

7. **Row pattern recognition reluctant quantifier zero-min bug** — Henson Choi acknowledges SugJun's finding that reluctant quantifiers with min=0 (such as `A*?` and `A??`) always consume at least one row in PostgreSQL while Oracle allows zero-length matches; also discusses whether PostgreSQL should error on unused DEFINE variables like Oracle (ORA-62503) instead of silently removing them, and whether to impose Oracle's 200-bound quantifier limit. https://www.postgresql.org/message-id/CAAAe_zBFKp7bn9YUamzNiy7s2LQ3C9VXsFLRTyVTbk+ETLfZUQ@mail.gmail.com

8. **Dead code in logical decoding of speculative insertions** — Antonin Houska proposes that since commit 4daa140a2f50 added the INTERNAL_SPEC_ABORT change, it's no longer necessary to handle "pending speculations" when receiving the next INTERNAL_SPEC_INSERT change, suggesting cleanup of dead code paths in logical decoding. https://www.postgresql.org/message-id/23256.1772702981@localhost

9. **Pass-by-value Bitmapset using tagged pointers continues** — Thomas Munro's immediate Bitmapset prototype using tagged Node pointers (zero bit = 1 for unboxed values) receives continued discussion, with the approach storing bitmaps inline in 63/31 bits for sets fitting in one word and enabling fast register-based comparisons like `if (bms_is_immediate(a)) return a == b`. https://www.postgresql.org/message-id/CA%2BhUKGJdzw6tSTQrBZNe2f0tAr%2BGdttiSS7-b0aVwPDfi3uh3A@mail.gmail.com

10. **astreamer_lz4 output pointer advancement bug committed** — Chao Li's fix for astreamer_lz4_decompressor_content() advancing next_out using cumulative bytes_written instead of just the current iteration's out_size gets addressed; the double-counting bug was hard to hit in practice because the default 1KB output buffer is typically filled in one or two iterations. https://www.postgresql.org/message-id/0594CC79-1544-45DD-8AA4-26270DE777A7@gmail.com
