# pgsql-hackers digest — Mar 6, 2026

1. **pg_resetwal.c duplicate '0' in hex validation no longer credits trivial reporters** — Chao Li confirms that Michael Paquier's recent batch commit 462fe0ff intentionally stopped crediting reporters of typo-like trivial fixes as an experiment to reduce processing overhead, with committers discussing a more lightweight process for the increasing volume of such patches. https://www.postgresql.org/message-id/0574F265-2FD9-40F7-9D04-8E9DF3E211D8%40gmail.com

2. **DSA pagemap out-of-bounds bug gets demonstration test patch** — Paul Bunn provides a new test patch to validate the make_new_segment bug where Path 2 (odd-sized segments) allocates pagemap with `usable_pages` entries but FreePageManager hands out pages with indices from `metadata_pages` to `metadata_pages + usable_pages - 1`, causing out-of-bounds access; the test uses hard-coded x64 platform assumptions and is meant for validation rather than permanent inclusion. https://www.postgresql.org/message-id/753FFCD4-D37F-4451-9942-A8B590090CA1%40gmail.com

3. **Dead code in logical decoding of speculative insertions identified** — Antonin Houska proposes cleanup of code paths that handle "pending speculations" when receiving the next INTERNAL_SPEC_INSERT change, arguing that commit 4daa140a2f50's addition of INTERNAL_SPEC_ABORT changes makes these paths unnecessary in logical decoding. https://www.postgresql.org/message-id/23256.1772702981%40localhost

4. **gistGetFakeLSN() returns incorrect LSNs at page boundaries** — Andres Freund discovers that gistGetFakeLSN() uses GetXLogInsertRecPtr() which returns the start of the next record, but when the last record ends at a page boundary this returns an LSN pointing after the xlog page header instead of directly to the start of the page, causing "xlog flush request is not satisfied" errors; triggered when generalizing the mechanism to other indexes in the prefetching patchset. https://www.postgresql.org/message-id/vf4hbwrotvhbgcnknrqmfbqlu75oyjkmausvy66ic7x7vuhafx%40e4rvwavtjswo

5. **Clearing VM doesn't register VM buffer in WAL record** — Melanie Plageman and Andres Freund notice that heap_{update,insert,delete}() don't register the VM buffer when clearing the visibility map, questioning whether all modified buffers need to be registered in WAL records to generate FPIs and avoid checksum failures. https://www.postgresql.org/message-id/CAAKRu_bn%2Be7F4yPFBgFbnP%2BsyJRKyNK092bjD2LKvZW7O4Svag%40mail.gmail.com

6. **Add starelid, attnum to pg_stats gets CF entry** — Corey Huinker creates commitfest entry 6568 for the patch adding relation OID and attribute number columns to pg_stats view to enable better pg_dump handling of extended statistics. https://www.postgresql.org/message-id/CADkLM%3Dcz%3DbEvRRj0mSffMrVW56M%3D1O-KqavCZv19on-MQrkZwg%40mail.gmail.com

7. **Generating function default settings from pg_proc.dat committed** — Tom Lane pushes the patch with a comment in system_views.sql advising that views not meant to be publicly readable should have their underlying function permissions adjusted in pg_proc.dat, since functions are publicly executable by default. https://www.postgresql.org/message-id/186784.1772750646%40sss.pgh.pa.us

8. **import_pg_statistic() pfree vs heap_freetuple is actually correct** — Yonghao Lee reports that import_pg_statistic() should use heap_freetuple(pgstup) instead of pfree(pgstup) to properly free both HeapTupleData and underlying t_data, but Tomas Vondra points out that heap_freetuple() is just defined as pfree() so the current code is correct given how heap_form_tuple() allocates tuples. https://www.postgresql.org/message-id/tencent_7BD47F423578A1DB8940FFD495651197A808%40qq.com

9. **BlockNumber misused as count type in multiple places** — Chao Li notices that BlockNumber (which has special values like InvalidBlockNumber and MaxBlockNumber) is used in several places to represent counts rather than block identifiers, such as LVRelState's rel_pages field and system_time_samplescangetsamplesize's pages parameter; asks whether these should be cleaned up to use int or other count types. https://www.postgresql.org/message-id/96FF4104-7891-4ED7-90E3-47FF1CD6F34D%40gmail.com

10. **TeardownHistoricSnapshot() has unused is_error parameter** — Ci Chaoyun proposes removing the is_error parameter from TeardownHistoricSnapshot() which was introduced in commit b89e151054 for logical decoding but has never been used, as the function just sets two global pointers to NULL regardless of the parameter value. https://www.postgresql.org/message-id/tencent_0602D4A244D19D1513EBB209%40qq.com
