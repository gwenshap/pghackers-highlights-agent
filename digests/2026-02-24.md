# pgsql-hackers digest — Feb 24, 2026

1. **Portable StaticAssertExpr without GCC extensions** — Peter Eisentraut proposes replacing the statement-expression-based StaticAssertExpr() with a struct-based implementation for C (placing static_assert inside a struct definition) and lambda-based for C++, eliminating dependency on nonstandard GCC extensions while keeping MSVC <19.33 workaround for a compiler bug. https://www.postgresql.org/message-id/5fa3a9f5-eb9a-4408-9baf-403d281f8b10@eisentraut.org

2. **Check for C23 memset_explicit() and NetBSD explicit_memset()** — Peter Eisentraut adds configure checks for C23's memset_explicit() (now in NetBSD 11, FreeBSD 15, glibc 2.43) and NetBSD's explicit_memset() as alternatives for implementing explicit_bzero(), with the C23 standard function taking precedence to future-proof as availability grows. https://www.postgresql.org/message-id/c4701776-8d99-41da-938d-88528a3adc15@eisentraut.org

3. **Optimize SELECT * in EXISTS per SQL standard** — Peter Eisentraut proposes transforming `EXISTS (SELECT * FROM ...)` to use an empty select list instead of expanding the star, matching the SQL standard's requirement that SELECT * in EXISTS should resolve to an arbitrary literal and eliminating the need for the `SELECT 1` idiom currently recommended in documentation. https://www.postgresql.org/message-id/9b301c70-3909-4f0f-98ca-9e3c4d142f3e@eisentraut.org

4. **Custom plan nodes can't handle ROWID_VAR in targetlist** — Alexander Kuzmenkov reports that TimescaleDB's Append-like custom node hits an impossible situation where ROWID_VARs must be in the output targetlist to satisfy Projection nodes but trigger assertions in set_customscan_references(); proposes replacing ROWID_VARs in root->processed_targetlist after processing them. https://www.postgresql.org/message-id/CALzhyqwk0V=_JVP7XLdYdcozM8itoVJkOmp+LxeHYOuTDLBAGg@mail.gmail.com

5. **EXCEPT TABLE patch should reject non-root partitions** — Amit Kapila suggests simplifying the publication EXCEPT clause implementation by initially rejecting non-root partitioned tables with ERROR, since much complexity comes from partition handling; also requests avoiding double invalidation of except-listed tables and enabling ALTER PUBLICATION SET EXCEPT TABLE for removal. https://www.postgresql.org/message-id/CAA4eK1+GuzCJZ80pAKZbqtMtr3RTPABtUQdvNvzn8RsCw+rQ6Q@mail.gmail.com

6. **Protocol greasing enabled by default in libpq** — Jacob Champion commits code to send PG_PROTOCOL_GREASE and test_protocol_negotiation by default and fail connections if servers claim support, providing feedback to noncompliant implementations; users can still connect to old servers via max_protocol_version=3.0, but this will be reverted before PG19 RC1 since it doesn't handle negotiation with future server versions yet. https://www.postgresql.org/message-id/E1vub8B-000rlS-05@gemulon.postgresql.org

7. **ProcWakeup() clears wrong waitStart** — Chao Li catches a typo in ProcWakeup() where `pg_atomic_write_u64(&MyProc->waitStart, 0)` should operate on the parameter `proc` instead of MyProc, incorrectly clearing the caller's waitStart instead of the awakened backend's and potentially leaving stale values. https://www.postgresql.org/message-id/537BD852-EC61-4D25-AB55-BE8BE46D07D7@gmail.com

8. **pg_stat_replication lag shows NULL during active replication** — Shinya Kato reports that pg_stat_replication.*_lag sometimes shows NULL when startup process replays WAL before walreceiver sends flush notification, violating the assumption that two consecutive applyPtr==sentPtr messages must come from wal_receiver_status_interval; proposes checking all lag values are -1 before setting clearLagTimes. https://www.postgresql.org/message-id/CAOzEurTzcUrEzrH97DD7+Yz=HGPU81kzWQonKZvqBwYhx2G9_A@mail.gmail.com

9. **Shutdown hang root cause is missing asyncXactLSN update** — Anthonin Bonnefoy traces the shutdown hang deeper and finds that XLogBackgroundFlush backs off to completed page boundaries, but uncommitted pages containing continuation records aren't flushed because asyncXactLSN isn't updated when transactions without xid are rolled back; proposes calling XLogSetAsyncXactLSN in RecordTransactionAbort even without xid. https://www.postgresql.org/message-id/CAO6_XqrZEREa5d+dyjahX6bteBhoN=8Jid-3a4f6Q35sWrv9eg@mail.gmail.com

10. **Remove array_ref() and array_set() wrappers** — David Geier proposes removing the array_ref() and array_set() wrappers (relicts from 2015) since only 5 calls to each remain on master, simplifying code by using array_get_element() and array_set_element() directly which take Datum arguments like most other array functions. https://www.postgresql.org/message-id/5bb669cc-7c48-4a50-b0b6-0612f95426d1@gmail.com

11. **Wrong results with grouping sets from unsafe RTE deletion** — Tom Lane flags commit ffe12d1d2 as unsafe because `list_delete_cell(query->rtable, lc)` changes rangetable indices of all following RTEs, which only appears to work if RTE_GROUP is always last; suggests converting the RTE to an innocuous RTE_RESULT instead. https://www.postgresql.org/message-id/3472344.1771858107@sss.pgh.pa.us
