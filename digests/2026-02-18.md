# pgsql-hackers digest — Feb 18, 2026

1. **Out-of-cycle release scheduled for February 26** — Jonathan Katz announces an emergency release to fix two critical regressions from the February 12 update: substring() raising encoding errors on non-ASCII column data, and standbys halting with "could not access status of transaction" errors. https://www.postgresql.org/message-id/4746c150-0af6-4352-ac53-1415fa93fae9@postgresql.org

2. **Generating function defaults from pg_proc.dat** — Tom Lane posts a draft patch that eliminates manual default argument specifications in system_views.sql by having genbki.pl auto-generate function_defaults.sql from new proargdflts/provariadicdflt fields in pg_proc.dat, converting 37 existing functions to use the approach. https://www.postgresql.org/message-id/1288023.1771292185@sss.pgh.pa.us

3. **Race condition causes "relation deleted while still in use"** — Alexander Lakhin reports a buildfarm failure where concurrent GRANT/VACUUM operations trigger "relation deleted while still in use" errors, providing a reproduction script demonstrating the issue with 40 concurrent sessions. https://www.postgresql.org/message-id/9f7cc148-55d1-4062-8229-b6886d7aa380@gmail.com

4. **Request to revert back-patched ABI breaks** — Peter Eisentraut requests reverting CacheInvalidateHeapTupleInplace() and PrepareToInvalidateCacheTuple() signature changes from the backbranches, arguing they are unnecessary ABI/API breaks causing packaging pain for non-PGXN tableam modules with no real benefit. https://www.postgresql.org/message-id/ff48df7b-8b82-4cf4-a340-668dadeff88f@eisentraut.org

5. **Script to detect uninitialized WAL record padding** — Zsolt Parragi proposes a headercheck-style script that automatically detects WAL record struct padding issues across the codebase, finding several cases where padding isn't properly handled and suggesting enforcement for core code (though extensions can't be constrained). https://www.postgresql.org/message-id/CAN4CZFOQjNQNSPKx%2BLKfHkcO7KFB%2BZjmdXEyhO%2BsYs4Qiqj-%2BQ@mail.gmail.com

6. **Standard die() handler for background workers** — Heikki Linnakangas proposes replacing bgworker_die() with the standard SIGTERM die() handler, noting that the current background worker default is completely unsafe and can self-deadlock against memory allocations or confuse stderr streams. https://www.postgresql.org/message-id/5238fe45-e486-4c62-a7f3-c7d8d416e812@iki.fi

7. **Add assertion for palloc in signal handlers** — Nathan Bossart implements an assertion to detect memory allocations inside signal handlers using the wrapper_handler infrastructure; check-world passes but manual testing with bgworker_die() confirms the assertion catches unsafe behavior. https://www.postgresql.org/message-id/aZTqurNQG-cDzJcL@nathan

8. **Add signal source PID/UID to termination messages** — Jakub Wartak proposes using Linux SA_SIGINFO to log which PID/UID sent termination signals to backends, eliminating time-intensive investigations to identify which script/user killed a backend in multi-department environments. https://www.postgresql.org/message-id/CAKZiRmyrOWovZSdixpLd3PGMQXuQL_zw2Ght5XhHCkQ1uDsxjw@mail.gmail.com

9. **amcheck: verify all index keys match heap tuples** — Andrey Borodin adds a new "indexallkeysmatch" option to bt_index_check() that verifies each B-tree index tuple points to a heap tuple with the same key (the reverse of heapallindexed), using a Bloom filter to avoid excessive random heap I/O; designed to catch corruptions where index keys differ from heap keys. https://www.postgresql.org/message-id/432626F9-65DF-4F0D-B345-26CFC3E2CFAC@yandex-team.ru

10. **Skip NULL-checking loop for NOT IN selectivity** — Ilia Evdokimov proposes using memchr() to quickly detect NULL elements in constant arrays before entering the per-element selectivity estimation loop, allowing immediate return of selectivity=0.0 for `x NOT IN (NULL, ...)` cases and avoiding expensive per-element estimation work for large lists. https://www.postgresql.org/message-id/eaa2598c-5356-4e1e-9ec3-5fd6eb1cd704@tantorlabs.com
