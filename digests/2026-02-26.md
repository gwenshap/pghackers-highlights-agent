# pgsql-hackers digest — Feb 26, 2026

1. **amcheck missing corruption in allequalimage validation** — Chao Li discovers that amcheck's allequalimage validation only reports metapage corruption when an interval opfamily is present, silently ignoring corruption in other cases because the ereport is inside the for loop; moving it outside ensures corruption is always reported with an optional interval-specific hint. https://www.postgresql.org/message-id/011ACC9C-CB87-4160-ACE7-4ED57AB86E15%40gmail.com

2. **GoAway protocol message needs test coverage** — Zsolt Parragi reviews the graceful shutdown patch and notes that the backend filtering logic differs slightly from SignalChildren; suggests adding minimal test coverage since the pytest framework is unlikely for PG19. https://www.postgresql.org/message-id/CAN4CZFMLpakQb8qohDAnrOoQ1-UrvmzJewZss95Y%2BMf_J%2BiNeA%40mail.gmail.com

3. **pg_dump --statistics-only fails on expression indexes** — Maksim Melnikov reports that pg_dump uses the wrong index's attribute names when processing indexes after an expression index, causing "could not find index attname" errors; attaches a simple fix to reset attribute name tracking between indexes. https://www.postgresql.org/message-id/be5fc489-587e-421f-bbb8-adb43cfd50f4%40postgrespro.ru

4. **Grouping expressions inside subqueries now implementable** — Tom Lane revisits a 30-year-old unimplemented case where grouping expressions like `a + b` aren't recognized inside subqueries, previously thought to require a custom equal() implementation; discovers a tractable approach that doesn't require exponential time or custom equality logic. https://www.postgresql.org/message-id/531183.1772058731%40sss.pgh.pa.us

5. **Convert ALL SubLinks to ANY for optimization** — Richard Guo proposes converting ALL SubLinks to negated ANY SubLinks using De Morgan's laws (e.g., `foo <> ALL (sub)` becomes `NOT (foo = ANY (sub))`), enabling hashed SubPlans and semijoin/antijoin optimization while maintaining identical worst-case performance with just a single boolean NOT overhead per outer tuple. https://www.postgresql.org/message-id/CAMbWs48P9d8p_MftXr7ZPb86HvOLu%3D3ovNz5By85JvSu9epNQA%40mail.gmail.com

6. **XLogFindNextRecord error propagation design discussion** — Anthonin Bonnefoy responds to Chao Li's suggestion to use XLogReaderGetLastError() helper instead of an errormsg parameter, arguing that the parameter signals "this function can fail" more explicitly and that error messages are typically printed shortly after the call, making lifetime concerns minimal. https://www.postgresql.org/message-id/CAO6_Xqqh-tWFMVAuXPnfB8HCGkeBoHK_AgSMZ-qoymb_1NUQjQ%40mail.gmail.com

7. **Shutdown hang reproduction script posted** — Anthonin Bonnefoy provides a script reproducing the indefinite shutdown hang due to unflushed FPI_FOR_HINT records, which sets up logical replication and leaves the walsender stuck at 100% CPU with pg_stop waiting forever. https://www.postgresql.org/message-id/CAO6_XqrwjxFZU%3DXDVaiRCygQYFSjSpwPqJUgWKfaNdw_fVa73Q%40mail.gmail.com

8. **PITR pause bypassed by subxid overflow in XLOG_RUNNING_XACTS** — Matt Blewitt reports that when the first XLOG_RUNNING_XACTS has subxid_overflow=true, the standby stays in STANDBY_SNAPSHOT_PENDING and hot standby never activates, causing recovery_target_action='pause' to be silently bypassed; proposes forcing STANDBY_SNAPSHOT_READY at recovery target since overflowed subxids are always INPROGRESS without SubTrans lookups. https://www.postgresql.org/message-id/CACy-Nv24ZORVN9_S_yHF5Nsip45HKCBtKVNC3XdKgz%2B1wvGvEQ%40mail.gmail.com

9. **CompactAttribute sizing trades memory for instruction efficiency** — David Rowley explains that CompactAttribute is 8 bytes instead of 6 to enable single-LEA instruction indexing, while 6 bytes requires two LEA instructions plus extra bitwise-AND for attbyval checks, likely costing more CPU than the memory savings; also proposes starting a proper benchmarking suite around deform_bench. https://www.postgresql.org/message-id/CAApHDvpBuTZLOQLfDETa9U-je2scAe3_BNXZScwr3hLPc6Hf3g%40mail.gmail.com

10. **SLRU I/O error reporting generalized beyond 32-bit XIDs** — Maxim Orlov proposes adding custom callbacks for SLRU error messages since the module now handles various object types (MultixactId, MultiXactOffset, QueuePosition) beyond its original 32-bit TransactionId design, enabling better error messages and optionally including XID epoch. https://www.postgresql.org/message-id/CACG%3DezZZfurhYV%2B66ceubxQAyWqv9vaUi0yoO4-t48OE5xc0DQ%40mail.gmail.com
