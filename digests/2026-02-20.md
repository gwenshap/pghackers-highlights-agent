# pgsql-hackers digest — Feb 20, 2026

1. **Hash aggregate collisions cause excessive spilling** — Ants Aasma reports a serious performance issue where hash aggregates with >150 colliding keys grow past work_mem and enter a degenerate state, spilling one tuple at a time with O(n²) overhead; the issue appears related to parallel query plans with cascaded HashAggregate nodes and may require simplehash to support size-limited inserts. https://www.postgresql.org/message-id/CANwKhkPOZupu3PYQVdkMmYjquYVqG2v8XmCAuuVM9Eu13-Zw3g@mail.gmail.com

2. **IO histogram memory overhead concerns** — Andres Freund raises concerns about pg_stat_io_histogram's 30kB-per-backend memory usage, noting that planned expansions to IO types (e.g., bypass-shared-buffers) and contexts (e.g., index inner/leaf) could significantly increase overhead; proposes using log-base-4 buckets and reducing the number of histogram combinations tracked. https://www.postgresql.org/message-id/s7wmiyblwwsjdsnzcojh77mvj4qnnfhpeng5qfnk7cybnslfhn@lpev3xq2mbdd

3. **Standby follows wrong timeline after switchover** — Andrey Borodin reports that XLogFileReadAnyTLI can silently apply divergent WAL from the wrong timeline during archive recovery, causing a standby to remain on an old primary's timeline after a planned HA switchover instead of following the promoted primary's new timeline. https://www.postgresql.org/message-id/85386EF6-16B7-4D62-86BE-526A10F93825@yandex-team.ru

4. **SLRU error messages need better 64-bit formatting** — Maxim Orlov proposes improving SLRU error messages to properly report 64-bit transaction IDs and multixid offsets; Heikki Linnakangas suggests using SLRU-specific callbacks instead of the generic "%u:%u" format since it's misleading for contexts like pg_async that use InvalidTransactionId. https://www.postgresql.org/message-id/5b4e458d-94f1-4ca3-ab72-aae8328e038d@iki.fi

5. **Assume availability of "inline" keyword** — Nathan Bossart proposes removing the configure check and __inline__ fallbacks since "inline" has been part of C99 and PostgreSQL now requires C11; meson builds already skip this check. https://www.postgresql.org/message-id/aZdGbDaV4_yKCMc-@nathan

6. **Use standard C23 and C++ attributes** — Peter Eisentraut proposes using standard [[nodiscard]], [[noreturn]], and [[maybe_unused]] attributes when available in C23/C++, allowing removal of GCC-specific and MSVC-specific fallbacks for pg_noreturn and improving portability for non-GCC C23 compilers. https://www.postgresql.org/message-id/a7e4ad20-57d9-4dfb-bdac-6e4246251d02@eisentraut.org

7. **Call for hacker mentoring applications 2026** — Robert Haas announces that three-quarters of the 1:1 mentoring relationships from last year are still ongoing and opens applications for new mentees; the program pairs active pgsql-hackers contributors with committers and is intended for developers committing significant time with potential committer aspirations. https://www.postgresql.org/message-id/CA+TgmoZ3G1u0wSwKFSUkhxyYjpacsfsnzJVHd6L48bD7AisdsA@mail.gmail.com

8. **Checkpoint reason exposed in completion logs** — Fujii Masao commits a patch that adds checkpoint reason details to completion log messages, making it easier to understand why checkpoints occurred without needing to correlate start and end messages. https://www.postgresql.org/message-id/CAHGQGwEeLpeCSffn%3Di0s0-zbHc4XLO9sF72hVE%3D9%2BRCGYS6%3DxQ@mail.gmail.com
