# pgsql-hackers digest — Mar 4, 2026

1. **Pass-by-value Bitmapset using tagged pointers for immediate values** — Thomas Munro prototypes "immediate" Bitmapset values that skip allocation by tagging Node pointers with zero bit = 1 to indicate unboxed values, leaving 63 (or 31) bits to store the bitmap inline; immediate representation works for sets fitting in one word (except when 63/31 is the highest member since the tag eats a bit), with functions like bms_equal() checking `if (bms_is_immediate(a)) return a == b` for fast register-based comparisons. https://www.postgresql.org/message-id/CA%2BhUKGJdzw6tSTQrBZNe2f0tAr%2BGdttiSS7-b0aVwPDfi3uh3A@mail.gmail.com

2. **RegisterExtensionExplainOption sizeof bug causes crash after 8 options** — Joel Jacobson discovers that explain_state.c used `sizeof(char *)` instead of `sizeof(ExplainExtensionOption)` in allocations, causing crashes when extensions register more than 8 EXPLAIN options; Andreas Karlsson suggests repalloc_array() would have prevented the bug, though Michael Paquier kept the simpler fix for consistency with existing MemoryContextAlloc() usage. https://www.postgresql.org/message-id/3b633bb7-f34f-4daf-82b3-038d87ef289b@proxel.se

3. **astreamer_lz4 output pointer advancement bug in decompressor** — Chao Li finds that astreamer_lz4_decompressor_content() advances next_out using cumulative bytes_written instead of just the current iteration's out_size, effectively double-counting progress; the bug is hard to hit in practice because the default 1KB output buffer is typically filled in one or two LZ4F_decompress() iterations, but can be triggered by artificially limiting out_size. https://www.postgresql.org/message-id/0594CC79-1544-45DD-8AA4-26270DE777A7@gmail.com

4. **vac_truncate_clog() volatile qualification narrowed to specific fields** — Peter Eisentraut commits Bertrand Drouvot's patch that removes the broad volatile qualifier on dbform and instead applies it only to datfrozenxid_p and datminmxid_p pointers, matching the pattern from 2d2e40e3bef and eliminating compiler warnings while maintaining race condition protection; also applies the same pattern to vac_update_datfrozenxid() for consistency. https://www.postgresql.org/message-id/4b2c1e2b-1bad-4690-a86d-d20727729abe@eisentraut.org

5. **UBSAN crash in EventTriggerCollectAlterTSConfig with NULL memcpy** — Florin Irion discovers that DROP MAPPING unconditionally calls EventTriggerCollectAlterTSConfig() with NULL dictIds and ndicts=0, reaching `memcpy(command->d.atscfg.dictIds, NULL, 0)` which triggers SIGABRT under -fsanitize=undefined; the bug has been latent since b488c580aef (9.5) because without an active event trigger the function returns early, but crashes when ddl_command_end triggers are installed. https://www.postgresql.org/message-id/c6fff161-9aee-4290-9ada-71e21e4d84de@gmail.com

6. **DSA pagemap out-of-bounds bug in make_new_segment odd-sized path** — Paul Bunn identifies a bug where make_new_segment()'s Path 2 (odd-sized segments) allocates pagemap with `usable_pages` entries but FreePageManager hands out pages with indices from `metadata_pages` to `metadata_pages + usable_pages - 1`, causing out-of-bounds access when `metadata_pages >= 1`; bug caused parallel hash join crashes on Postgres 15 with workers computing pageno 196993 beyond pagemap's 196609 entries. https://www.postgresql.org/message-id/ba161ba1-9d5f-409d-9826-40d076d4ca2b@me.com

7. **pg_combinebackup produces incorrect VM fork size after truncation** — Amul Sul reports that when a relation spanning multiple segments (>1GB) is truncated down to a single segment via VACUUM, the SMGR_TRUNCATE_ALL WAL record causes pg_combinebackup to reconstruct the Visibility Map fork with an incorrect "insanely high" size equal to the main fork; provides reproducer showing WAL summarizer may be mixing up information between relation forks. https://www.postgresql.org/message-id/CAAJ_b97PqG89hvPNJ8cGwmk94gJ9KOf_pLsowUyQGZgJY32o9g@mail.gmail.com

8. **pg_stat_replication lag columns show NULL when WalRcvForceReply triggers extra message** — Shinya Kato discovers that lag columns show NULL during active replication when startup process calls WalRcvForceReply() after fast replay, causing walreceiver to send two consecutive messages with applyPtr == sentPtr, violating the assumption that the second such message must come from wal_receiver_status_interval; proposes tracking whether force_reply triggered the message to distinguish the two cases. https://www.postgresql.org/message-id/CAHGQGwE%3DkyQ%2BYnGPn8zpZ959%2B3ywg8OR_Nu__uXxxuE0E%2BY_Zg@mail.gmail.com

9. **Shutdown hang fix offers two approaches for XactLastRecEnd flushing** — Anthonin Bonnefoy provides v4 with two alternatives: 0001 calls XLogSetAsyncXactLSN(XactLastRecEnd) in RecordTransactionAbort() when `!isSubXact && XactLastRecEnd != 0` to handle backlogs from selects pruning pages, while 0002 calls XLogFlush(WriteRqstPtr) in ShutdownXLOG() to flush everything before stopping walsenders, with the latter being simpler for backporting but potentially missing records from other backends. https://www.postgresql.org/message-id/CAO6_XqqKDV%2BAuP%3DGf4kRKPqzyYTsOyGd3LE8Jqkwi7EMPJpbhA@mail.gmail.com

10. **pg_dumpall --roles-only mutual exclusion simplified with check_mut_excl_opts macro** — Nathan Bossart stages a commit that adds check_mut_excl_opts() macro to option_utils.c for checking arbitrary numbers of mutually exclusive options, avoiding long lists of individual checks; limits new tests to one per call rather than exhaustive coverage, and defers derivative flags to a separate patch. https://www.postgresql.org/message-id/aacthjryoKZp398P@nathan
