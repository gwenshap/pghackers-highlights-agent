# pgsql-hackers digest — Feb 23, 2026

1. **ecpg test hangs on NetBSD resolved with IPC::Run upgrade** — Alexander Lakhin traces intermittent test hangs on the sidewinder buildfarm animal to an old version of Perl's IPC::Run module; upgrading from the 2023 version resolves the issue, suggesting a known bug in the test infrastructure dependency. https://www.postgresql.org/message-id/a30fb7fa-abda-425f-8269-371333b42417%40gmail.com

2. **Standby recovery fails with missing timeline history after 17.7 upgrade** — Fabrice Chapuis reports "record with incorrect prev-link" errors and missing timeline history file complaints after upgrading a standby from PostgreSQL 17.6 to 17.7, suggesting a regression in WAL recovery startup logic. https://www.postgresql.org/message-id/CAA5-nLBRB6t%2BCKq_pJTbVrqFB8j9r3J1YUirYBLYV%2B0-xpOWgw@mail.gmail.com

3. **Row pattern recognition adds reluctant quantifiers and DFS optimizations** — Henson Choi posts two patches that eliminate the altPriority field by using DFS early termination to guarantee ALT lexical ordering, and implement reluctant quantifiers by reversing DFS traversal order to explore shorter matches first; both optimizations leverage the insight that NFA state list order already encodes lexical priority. https://www.postgresql.org/message-id/CAAAe_zDcrF9_m5FnWFgdrCpxjTqdH2ZMDmpKXevMG4KBHJsw4w@mail.gmail.com

4. **EXCEPT TABLE patch split to simplify review** — Amit Kapila suggests splitting the publication EXCEPT clause implementation by first rejecting non-root partitioned tables with an ERROR, since much of the code complexity comes from partition handling; also requests avoiding double invalidation of except-listed tables. https://www.postgresql.org/message-id/CANhcyEUK_L%2B2Y%2BQX44Gkf%2BTCyz8YBCCT4zp1mVqizqYKkx4RVg@mail.gmail.com

5. **Draft release announcement for February 26 out-of-cycle releases** — Jonathan Katz posts the draft announcement for PostgreSQL 18.3 and minor releases, seeking review especially for guidance on post-update steps for users affected by the json[b]_strip_nulls() regression who already upgraded to affected versions. https://www.postgresql.org/message-id/312ba397-44b2-4332-84eb-6bf80dcec127@postgresql.org

6. **StaticAssertExpr() reimplemented without GCC extensions** — Peter Eisentraut proposes replacing the statement-expression-based StaticAssertExpr() with a struct-based implementation for C and lambda-based for C++, eliminating dependency on GCC extensions; keeps MSVC workaround for versions before 19.33 which had a compiler bug. https://www.postgresql.org/message-id/5fa3a9f5-eb9a-4408-9baf-403d281f8b10@eisentraut.org

7. **Add configure checks for memset_explicit() and explicit_memset()** — Peter Eisentraut proposes detecting C23's memset_explicit() and NetBSD's explicit_memset() as alternatives for implementing explicit_bzero(), with the C23 standard function taking precedence; already supported in NetBSD 11, FreeBSD 15, and glibc 2.43. https://www.postgresql.org/message-id/c4701776-8d99-41da-938d-88528a3adc15@eisentraut.org

8. **Optimize SELECT * in EXISTS to match SQL standard** — Peter Eisentraut proposes transforming `EXISTS (SELECT * FROM ...)` to use an empty select list (zero columns) rather than expanding the star, matching the SQL standard's requirement that SELECT * in EXISTS should resolve to an arbitrary literal; would eliminate the need for the `SELECT 1` idiom recommended in documentation. https://www.postgresql.org/message-id/9b301c70-3909-4f0f-98ca-9e3c4d142f3e@eisentraut.org

9. **Custom plan nodes can't handle ROWID_VAR in processed_targetlist** — Alexander Kuzmenkov reports that TimescaleDB's Append-like custom node hits an impossible situation where ROWID_VARs must be in the output targetlist to satisfy Projection nodes, but cannot be present due to assertion failures in set_customscan_references(); proposes replacing ROWID_VARs in root->processed_targetlist after processing them. https://www.postgresql.org/message-id/CALzhyqwk0V%3D_JVP7XLdYdcozM8itoVJkOmp%2BLxeHYOuTDLBAGg@mail.gmail.com

10. **Resizable shared structures under page size treated as fixed** — Ashutosh Bapat explains that resizable shared memory structures with max_size smaller than page_size will be treated as fixed-size with no actual madvise() operations, only metadata updates, since sub-page resizing serves no practical purpose and page sizes vary widely across systems (especially with huge pages). https://www.postgresql.org/message-id/CAExHW5so6VSxBC-1V%3D35229Z1%2Bdw5vhw8HxHg9ry7UzceKcXzA@mail.gmail.com
