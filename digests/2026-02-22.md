# pgsql-hackers digest — Feb 22, 2026

1. **Partial Mode in aggregate functions needs documentation clarification** — Marcos Pegoraro points out that the documentation's "Partial Mode" terminology is confusing to users who expect it to relate to FILTER clauses rather than parallel aggregation eligibility, and proposes better wording and adding FILTER documentation to the aggregate functions page. https://www.postgresql.org/message-id/CAB-JLwaQSpjTNHtzMcaHw5yoKUi%2BtD444bT%2BOsbCYo3CBf%3DWLw@mail.gmail.com

2. **Fix memory leak in postmaster startup** — Henrik TJ reports a minor memory leak when postgres is started with the -D flag, where the strdup() allocation is never freed; found with valgrind but inconsequential since postmaster doesn't exit during normal operation. https://www.postgresql.org/message-id/e84ede22-1b46-0780-64e4-5db4a1e5236f@0x48.dk

3. **Spec test for SSI SxactGlobalXmin race condition** — Josh Curtis provides an isolation test that reproduces the race condition when reading PredXact->SxactGlobalXmin without proper locking, though notes the test logic is brittle and may not be suitable for merging. https://www.postgresql.org/message-id/CAEkjoh06tRVx_x%2BC-igg0GMaXVqYegJT006QHm09pRJuCjPbiA@mail.gmail.com

4. **Pattern matching for pg_regress expected outputs** — Alexandre Felipe proposes adding selective pattern matching capabilities to pg_regress to handle test output variations (like those from different block sizes), with support for ignoring numbers in specific lines via a human-readable format documented with executable examples. https://www.postgresql.org/message-id/CAE8JnxP0js27RrunxXktvfmnum7csoBe2q_R%2Bsj08hoqDNG3Zg@mail.gmail.com

5. **xmlvalidate patch needs predefined roles for security** — Marcos Magueta and reviewers discuss whether unrestricted xmlvalidate() access could lead to CPU/memory abuse and whether predefined roles are the appropriate mechanism to control access to XML schema validation functionality. https://www.postgresql.org/message-id/CAN3aFCfkrkOJ%2BR39x%3D9qvXMGLE3yuL9fZdNyRa5V%3DBAdGGu%3D-g@mail.gmail.com

6. **Table comments shouldn't copy with INCLUDING COMMENTS** — Hüseyin Demir raises concerns that copying table comments via CREATE TABLE LIKE INCLUDING COMMENTS is wrong more often than right, since table comments describe purpose/context (e.g., "staging table for pipeline X") rather than schema structure, unlike column or constraint comments. https://www.postgresql.org/message-id/177174751973.626.7673368092428390674.pgcf@coridan.postgresql.org

7. **Record with incorrect prev-link after 17.7 upgrade** — Fabrice Chapuis reports a "record with incorrect prev-link" error after upgrading a standby from PostgreSQL 17.6 to 17.7, with the server complaining about missing timeline history files during recovery startup. https://www.postgresql.org/message-id/CAAAe_zDcrF9_m5FnWFgdrCpxjTqdH2ZMDmpKXevMG4KBHJsw4w@mail.gmail.com

8. **Row pattern recognition: DFS early termination and reluctant quantifiers** — Henson Choi posts two incremental patches that implement ALT lexical ordering via DFS early termination (eliminating the altPriority field) and add reluctant quantifier support by reversing DFS traversal order to explore shorter matches first. https://www.postgresql.org/message-id/CAAAe_zDcrF9_m5FnWFgdrCpxjTqdH2ZMDmpKXevMG4KBHJsw4w@mail.gmail.com

9. **Skipping schema changes needs invalidation comments** — Amit Kapila reviews the EXCEPT TABLE patch and requests clarifying comments about where all tables are invalidated, why exceptlist is only formed for RELKIND_RELATION, and suggests improving error message style to match PostgreSQL conventions. https://www.postgresql.org/message-id/CAA4eK1KESu4%3DW6j4CQkKv5nzNJgtJyYBsg3E5K%2BLcwOr3t0WKw@mail.gmail.com
