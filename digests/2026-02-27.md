# pgsql-hackers digest — Feb 27, 2026

1. **Convert ALL SubLinks to ANY for optimization** — Richard Guo proposes transforming `foo op ALL (sub)` to `NOT (foo negator_op ANY (sub))` using De Morgan's laws, enabling hashed SubPlans and semijoin/antijoin optimization with negligible overhead (just one boolean NOT per outer tuple) and no regression risk since worst-case execution remains identical to the current nested-loop ALL SubPlan. https://www.postgresql.org/message-id/CAMbWs48P9d8p_MftXr7ZPb86HvOLu%3D3ovNz5By85JvSu9epNQA@mail.gmail.com

2. **PITR pause bypassed by subxid overflow in XLOG_RUNNING_XACTS** — Matt Blewitt reports that when the first XLOG_RUNNING_XACTS has subxid_overflow=true, the standby stays in STANDBY_SNAPSHOT_PENDING and hot standby never activates, causing recovery_target_action='pause' to be silently bypassed; proposes forcing STANDBY_SNAPSHOT_READY at recovery target since overflowed subxids are always INPROGRESS without SubTrans lookups. https://www.postgresql.org/message-id/CACy-Nv24ZORVN9_S_yHF5Nsip45HKCBtKVNC3XdKgz%2B1wvGvEQ@mail.gmail.com

3. **Shutdown hang reproduction script posted** — Anthonin Bonnefoy provides a script reproducing the indefinite shutdown hang due to unflushed FPI_FOR_HINT records, which sets up logical replication and leaves the walsender stuck at 100% CPU with pg_stop waiting forever. https://www.postgresql.org/message-id/CAO6_XqrwjxFZU%3DXDVaiRCygQYFSjSpwPqJUgWKfaNdw_fVa73Q@mail.gmail.com

4. **SLRU I/O error reporting generalized beyond 32-bit XIDs** — Maxim Orlov proposes adding custom callbacks for SLRU error messages since the module now handles various object types (MultixactId, MultiXactOffset, QueuePosition) beyond its original 32-bit TransactionId design, enabling better error messages and optionally including XID epoch. https://www.postgresql.org/message-id/CACG%3DezZZfurhYV%2B66ceubxQAyWqv9vaUi0yoO4-t48OE5xc0DQ@mail.gmail.com

5. **Invalid stats data in extended statistics causes crashes** — Michael Paquier discovers two defects in extended statistics handling where lookup_var_attr_stats() doesn't check for invalid expression stats and pg_dump fails to restore NULL expression stats correctly, both introduced in v15 when expression support was added; proposes fixes to handle the NULL markers that indicate failed stats computation. https://www.postgresql.org/message-id/aaDrJsE1I5mrE-QF@paquier.xyz

6. **SASLprep implementation doesn't prohibit ASCII control characters** — Michael Paquier finds that the ASCII-only fast path in pg_saslprep() incorrectly allows prohibited characters like control characters (0x00-0x1F) and DEL (0x7F), violating RFC 4013; proposes making the implementation RFC-compliant with minimal performance impact and no practical downside since current behavior treats prohibited bytes identically anyway. https://www.postgresql.org/message-id/aaEJ-El2seZHeFcG@paquier.xyz

7. **COMMENT ON with empty string should be documented as NULL** — Chao Li proposes clarifying the COMMENT ON documentation to explicitly state that empty strings are treated as NULL and remove the comment, since this behavior differs from similar commands like SECURITY LABEL ON and isn't obvious from current docs. https://www.postgresql.org/message-id/CAHGQGwFJKg-aT5vajSU1v_B4K129u_SjZ3EGGHFSBhW967gcMA@mail.gmail.com

8. **EXCEPT TABLE publication queries may hurt performance on upgrade** — Andrei Lepikhov suggests adding `prexcept` as a second column to pg_publication_rel_prpubid_index since queries checking for excepted tables must scan all publication tables, which could be costly for users with hundreds or thousands of tables when only a few (or none) are actually excepted. https://www.postgresql.org/message-id/CAA4eK1Lxp8_HJv3sZNPx-oM1CUUi5p2UYa1PoVTe-QOEEp%2B3Ww@mail.gmail.com

9. **Documentation typo in alter_table.sgml** — Erik Rijkers catches subject-verb agreement error: "Replacing the expression of a virtual generated column do not require" should be "does not require". https://www.postgresql.org/message-id/3c258fac-04c3-1f9a-fabc-94ded0e2f7ec@xs4all.nl

10. **How REPACK concurrent changes reach replicas unclear** — Álvaro Herrera realizes while reviewing that he doesn't understand how REPACK's WAL messages for concurrent changes are transmitted to replicas and interspersed with other concurrent load, prompting him to return to deeper code review of the logical decoding implementation. https://www.postgresql.org/message-id/202602261101.5xvhvcgqcz2k@alvherre.pgsql
