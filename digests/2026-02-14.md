*pgsql-hackers digest — Feb 14, 2026*

1. **Reduce timing overhead of EXPLAIN ANALYZE using rdtsc?** — Andres Freund diagnoses why a patch to use rdtsc for faster timing shows slowdown with clock_gettime(): the overflow logic triggers after just 3 days of uptime when converting nanoseconds since boot, and suggests keeping measurements in the instr_time domain to avoid this. This matters for reducing EXPLAIN ANALYZE overhead which can significantly distort query performance measurements. [link](https://www.postgresql.org/message-id/aY5Si7r2SMe4fRPc%40alap3.anarazel.de)

2. **Former primary node stuck when restarted as standby** — Hayato Kuroda (Fujitsu) identifies a race condition where INSERT statements happening between wait_for_replay_catchup and teardown_node aren't guaranteed to replicate, causing the test to fail. The logs show background activity INSERTs occurring right before immediate shutdown, leaving unsynced WAL records. [link](https://www.postgresql.org/message-id/OS9PR01MB12149C0F968A40BA54BD4C16FF561A%40OS9PR01MB12149.jpnprd01.prod.outlook.com)

3. **Tuple radix sort improvements** — John Naylor addresses reviewer feedback on the v7 radix sort patch, confirming bugs in comments (MSB/LSB reversed), agreeing to use pointers instead of copying SortSupportData, and discussing type choices for tracking partition sizes. This work aims to speed up tuple sorting for certain data patterns. [link](https://www.postgresql.org/message-id/CANWCAZZA_AqWy7xw20O%3DjWG%2Bt0Cy4rUnvs1RaAABvSp3iLnGhg%40mail.gmail.com)

4. **64-bit XIDs discussion hits philosophical impasse** — Bruce Momjian reframes the 64-bit XID debate as fundamentally about design philosophy: should PostgreSQL prioritize API purity or balance trade-offs between design elegance and practical code changes, and optimize for general use-cases versus high-volume installations? Three committers have rejected the current approach as having "zero chance of being accepted." [link](https://www.postgresql.org/message-id/aY6ODCBi_PMG-3Tn%40momjian.us)

5. **Automatic sequence replication refinements** — Peter Smith reviews v4 of the sequence replication patch, suggesting the removal of a global variable should be split into a separate prerequisite patch for easier review, and questioning whether certain error states are even possible (suggesting Assert instead). This feature aims to keep sequences synchronized across logical replication. [link](https://www.postgresql.org/message-id/CAHut%2BPvbkDGj8qHMdeQftqgds2v71KNG9PeC6TDCKYQn_AAVCA%40mail.gmail.com)

6. **Uninitialized padding in xl_running_xacts WAL records** — Anthonin Bonnefoy discovers that RUNNING_XACTS records contain random data from uninitialized 3-byte padding after subxid_overflow, visible via hexdump of WAL files. The fix is simple: zero the xl_running_xacts structure with MemSet in LogCurrentRunningXacts. [link](https://www.postgresql.org/message-id/CAO6_Xqoxp7C%2By0L%3D%3DxZXH5V%3D9PjpBx4T9vJYs87EbxFp_9nwOA%40mail.gmail.com)

7. **Greedy join search (GOO) shows promising results** — Lakshmi tests the v4 GOO patch and reports planning time of ~3.2ms for 20-table joins versus ~48-51ms for DP/GEQO, while maintaining comparable execution costs. Even on small joins GOO plans faster than both alternatives, suggesting it could be a practical middle ground between exhaustive DP search and randomized GEQO. [link](https://www.postgresql.org/message-id/CAEvyyTi1M6JhHb6sR%2BxK-kp2bezMoADSC%2BRY2A%2BDbdEn%2B_BLxA%40mail.gmail.com)

8. **Better shared memory management framework** — Ashutosh Bapat continues Heikki's work on a new API for managing shared memory structures using descriptors (ShmemStructDesc) that bundle size, initialization callbacks, and pointers together, replacing the current scattered ShmemInitStruct() calls. This proof-of-concept aims to make shared memory management more uniform and easier for extensions. [link](https://www.postgresql.org/message-id/CAExHW5vM1bneLYfg0wGeAa%3D52UiJ3z4vKd3AJ72X8Fw6k3KKrg%40mail.gmail.com)

9. **JIT default changing to off** — Jelte Fennema-Nio marks the patch to disable JIT by default as "ready for committer" after Andres Freund's +1, citing that partitioning becoming more common combined with LLVM getting slower over time makes this the right call until substantial improvements are made. [link](https://www.postgresql.org/message-id/CAGECzQQdO5OGnxe7bpN1usp%2Bku%2BtLBW%3DSwgLbrULVcFAjH5_yA%40mail.gmail.com)

10. **Signal handling redesign progress** — Heikki Linnakangas posts a new version of the interrupt-versus-signals rework with 64-bit interrupt masks (giving extensions more headroom), simplified postmaster-to-child signaling (mostly still using kill()), and a new RequestAddinInterrupt() function for extensions. The new README.md provides architectural overview. [link](https://www.postgresql.org/message-id/818bafaf-1e77-4c78-8037-d7120878d87c%40iki.fi)

11. **Temporal UPDATE/DELETE rebased** — Paul Jungwirth posts v65 (then v66) of the SQL:2011 temporal UPDATE/DELETE FOR PORTION OF patches, now rebased after the pg_range commit. This implements standard syntax for updating or deleting ranges of time-based data while automatically splitting rows as needed. [link](https://www.postgresql.org/message-id/CA%2BrenyWUCSyTMn3s03kviEN-oaVrJP-QkDQCLNfaY%3DMHV5QEiQ%40mail.gmail.com)
