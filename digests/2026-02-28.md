# pgsql-hackers digest — Feb 28, 2026

1. **Extended statistics crashes on invalid expression stats** — Michael Paquier discovers that lookup_var_attr_stats() doesn't check for NULL markers in expression statistics (which indicate failed stats computation), causing crashes when building plans, and that pg_dump fails to restore these NULL markers correctly; both bugs were introduced in v15 when expression support was added to extended statistics. https://www.postgresql.org/message-id/aaDrJsE1I5mrE-QF@paquier.xyz

2. **SASLprep ASCII fast path violates RFC by allowing control characters** — Michael Paquier finds that pg_saslprep()'s ASCII-only optimization incorrectly allows prohibited characters like control codes (0x00-0x1F) and DEL (0x7F), violating RFC 4013; proposes making it RFC-compliant with negligible performance impact since current behavior treats prohibited bytes identically anyway, just non-compliantly. https://www.postgresql.org/message-id/aaEJ-El2seZHeFcG@paquier.xyz

3. **CREATE OR REPLACE VIEW stacks duplicate event trigger commands** — Michael Paquier notices that replacing a view with additional columns triggers EventTriggerCollectSimpleCommand() for the ViewStmt and EventTriggerAlterTableEnd() for AT_AddColumnToView, causing the same command to appear twice in event trigger collection; proposes documenting this intentional behavior with tests rather than changing it since event triggers represent internal command structures. https://www.postgresql.org/message-id/aaFG9bqkEn0RhLJG@paquier.xyz

4. **DEFERRABLE lost when foreign key toggled NOT ENFORCED then ENFORCED** — Yasuo Honda reports that toggling a DEFERRABLE INITIALLY DEFERRED foreign key from NOT ENFORCED back to ENFORCED strips the deferrability properties from pg_trigger (tgdeferrable and tginitdeferred reset to 'f') even though pg_constraint remains correct, breaking SET CONSTRAINTS ... DEFERRED; proposes preserving trigger flags during constraint re-enforcement. https://www.postgresql.org/message-id/CAKmOUTms2nkxEZDdcrsjq5P3b2L_PR266Hv8kW5pANwmVaRJJQ@mail.gmail.com

5. **Stack allocation API to replace ad-hoc 1KB buffer pattern** — Thomas Munro proposes a new stack_buffer_alloc() API to replace the repeated pattern of using 1KB char arrays with palloc() fallback for locale functions, fixing issues with open-coding, missing pfree() leak risks, lack of type safety, and potential alignment bugs for wchar_t/UChar; considers whether to use alloca() where available since usage is metered. https://www.postgresql.org/message-id/CA%2BhUKG%2BixUUYOGRcuZpkk5pmJZaUQv6VCPAjdTZXFP5vA8jxcA@mail.gmail.com

6. **DETACH/ATTACH partition doesn't auto-refresh publication membership** — Nisha Moond finds that when a partition is detached from an excluded parent table in an EXCEPT TABLE publication, replication doesn't start automatically and requires manual REFRESH PUBLICATION, while re-attaching stops replication immediately without warning; suggests adding warnings/hints during DETACH/ATTACH to alert users about replication state changes. https://www.postgresql.org/message-id/CABdArM5zR5GUGquoyAeVJgRoQXzjXNa6WuF724Mfbt1RJ5cZ6Q@mail.gmail.com

7. **macOS file system ENOENT causes library loading failures** — Mark Dilger reports that stress testing on macOS reveals spurious ENOENT from pg_file_exists() when loading shared libraries, causing internal_load_library() to fail matching "/path/to/mytam.dylib" against "mytam" even though the library was already loaded during startup; proposes adding fallback logic to check for startup-loaded libraries when matching fails. https://www.postgresql.org/message-id/CAHgHdKvpzs5eUVOWSwcMjfFrnYfS-rk3TEUwK1vU_rFSJ3zb4g@mail.gmail.com

8. **REPACK avoids 1GB tuple limit by streaming toast chunks separately** — Antonin Houska implements toast chunk streaming in REPACK CONCURRENTLY where toast values are written to file first with individual pointers tracked, then the heap tuple is reconstructed by substituting the created toast pointers, avoiding the need to construct entire tuples in memory or palloc() flattened tuples that exceed MaxAllocSize. https://www.postgresql.org/message-id/87648.1772217509@localhost

9. **tid_blockno() and tid_offset() accessor functions proposed** — Ayush Tiwari proposes adding built-in tid_blockno(tid)->bigint and tid_offset(tid)->int functions to replace the clunky ctid::text::point hack commonly used for bloat analysis and page-level queries, using NoCheck macros from itemptr.h to safely handle user-supplied literals like (0,0). https://www.postgresql.org/message-id/CAJTYsWUzok2%2BmvSYkbVUwq_SWWg-GdHqCuYumN82AU97SjwjCA@mail.gmail.com

10. **PLpgSQL FOREACH IN JSON ARRAY proof of concept** — Pavel Stehule implements FOREACH x IN JSON ARRAY '[1,2,3]' syntax that's 3-4x faster than FOR IN SELECT FROM json_array_elements() by eliminating SQL executor overhead; assigns JSON object fields to variables by name (not position since jsonb doesn't preserve field order), with open questions about whether default mapping should be lax or strict mode. https://www.postgresql.org/message-id/CAFj8pRD9Jjv%2Bm%3D6DP6vWWn5NnZeTPH9eoPFCnA1JE5hRKRDMxQ@mail.gmail.com
