# pgsql-hackers digest — Feb 19, 2026

1. **Add signal source PID/UID to termination messages** — Jakub Wartak proposes using Linux SA_SIGINFO to log which PID/UID sent termination signals to backends, eliminating time-intensive investigations to identify which script/user killed a backend in multi-department environments. [link](https://www.postgresql.org/message-id/CAKZiRmyrOWovZSdixpLd3PGMQXuQL_zw2Ght5XhHCkQ1uDsxjw@mail.gmail.com)

2. **Modernize error message for malformed B-tree posting** — Kirill Reshke proposes changing the error code for posting list split failures from XX000 to XX002 (index corruption) and adding the index name to the message for consistency with other corruption errors. [link](https://www.postgresql.org/message-id/CALdSSPgQQJGvzMs_kMJfTFc%3DnHJNH1LxKiWo-xKr0HQBXF8UCg@mail.gmail.com)

3. **Use standard die() handler for SIGTERM in bgworkers** — Heikki Linnakangas proposes replacing bgworker_die() with the standard SIGTERM die() handler, noting that the current background worker default is completely unsafe and can self-deadlock against memory allocations or confuse stderr streams. [link](https://www.postgresql.org/message-id/CALdSSPhixPFWZWWmbGiS52GpHn2WRNP_Mn8e4jy%2BDoh4xxnnFQ@mail.gmail.com)

4. **Use LOCKMODE in parse_relation.c/.h** — Peter Eisentraut proposes using the proper LOCKMODE typedef in parse_relation.h instead of int, now that LOCKMODE is available in the narrow storage/lockdefs.h header rather than requiring the heavier storage/lock.h import. [link](https://www.postgresql.org/message-id/4bcd65fb-2497-484c-bb41-83cb435eb64d@eisentraut.org)

5. **OAuth shutdown_cb callback called at wrong time** — Zsolt Parragi reports that shutdown_cb is executed when the authentication memory context is cleaned up (immediately after auth) rather than at backend exit as documented, making validator state management problematic for features like token refresh. [link](https://www.postgresql.org/message-id/CAN4CZFOuMb_gnLvCwRdMybg_k8WRNJTjcij%2BPoQkuQHDUzxGWg@mail.gmail.com)

6. **Skip NULL-checking loop for NOT IN selectivity** — Ilia Evdokimov proposes using memchr() to quickly detect NULL elements in constant arrays before entering the per-element selectivity estimation loop, allowing immediate return of selectivity=0.0 for `x NOT IN (NULL, ...)` cases and avoiding expensive per-element estimation work for large lists. [link](https://www.postgresql.org/message-id/eaa2598c-5356-4e1e-9ec3-5fd6eb1cd704@tantorlabs.com)

7. **Killing off anoncvs.postgresql.org** — Magnus Hagander proposes shutting down the CVS web interface completely because it's getting hammered by AI bots, goes down frequently from the load, and appears to have near-zero real users; the CVS repository tarball would remain available on the download site. [link](https://www.postgresql.org/message-id/CABUevEyAuf6DG3dm0icnE1HMcS%2BEuF8AtaCpdEfnqwma1ib3Sg@mail.gmail.com)

8. **Split PGOAUTHDEBUG and add issuer-mismatch option** — Zsolt Parragi proposes splitting PGOAUTHDEBUG=UNSAFE into separate toggleable unsafe/safe settings and adding an issuer-mismatch option to allow testing validators when client and server issuers don't match. [link](https://www.postgresql.org/message-id/CAN4CZFMmDZMH56O9vb_g7vHqAk8ryWFxBMV19C39PFghENg8kA@mail.gmail.com)

9. **Convert SpinLock macros to static inline functions** — Nathan Bossart proposes converting spin.h macros to static inline functions as prerequisite work for adding signal handler assertions, also removing unused SpinLockFree() and unnecessary volatile qualifiers that predate making spinlocks compiler barriers. [link](https://www.postgresql.org/message-id/aZX2oUcKf7IzHnnK@nathan)

10. **Redundant restriction checks in apply_child_basequals** — Richard Guo notices that apply_child_basequals redundantly calls restriction_is_always_false/true after eval_const_expressions, even though NullTest deduction now happens during constant folding since planner improvements, wasting CPU cycles. [link](https://www.postgresql.org/message-id/CAMbWs4-vLmGXaUEZyOMacN0BVfqWCt2tM-eDVWdDfJnOQaauGg@mail.gmail.com)

11. **Remove obsolete SAMESIGN macro** — Richard Guo proposes removing the unused SAMESIGN macro definitions from brin_minmax_multi.c and timestamp.c, as manual integer overflow checks became obsolete when commit 4d6ad3125 introduced overflow-aware integer operations. [link](https://www.postgresql.org/message-id/CAMbWs4-NL3J3hQ3LzrwV-YUkQC18P%2BjM7ZiegQyAHzgdZev2qg@mail.gmail.com)
