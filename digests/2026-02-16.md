# pgsql-hackers digest — Feb 16, 2026

1. **MERGE doesn't check isolation level on TM_Updated path** — Alexander Korotkov notices that ExecMergeMatched() verifies IsolationUsesXactSnapshot() when handling TM_Deleted but not TM_Updated, even though EPQ works at repeatable read isolation; he provides a reproducible case and questions if this is intentional. [link](https://www.postgresql.org/message-id/CAPpHfdvzZSaNYdj5ac-tYRi6MuuZnYHiUkZ3D-AoY-ny8v%2BS%2Bw%40mail.gmail.com)

2. **CREATE ASSERTION deemed impractical** — Tom Lane explains why database-level assertions from SQL:2023 haven't been implemented: terrible performance implications, deadlock potential, and the security problem that any user with read permission could block updates by creating failing assertions. Everyone who's looked at this feature "has run away screaming." [link](https://www.postgresql.org/message-id/812111.1771119222%40sss.pgh.pa.us)

3. **Index prefetching shows regressions in fully-cached workloads** — Peter Geoghegan runs Alexandre Felipe's benchmarks and discovers the prefetching patch causes small slowdowns even when data is entirely cached, noting the benchmark doesn't account for OS filesystem cache; Andres Freund confirms tiny data sizes limit IO-bound testing and shows only 15.8% time spent on IO in 100k row tests. [link](https://www.postgresql.org/message-id/CAH2-Wzme0Gok57LkHEQQzNwJ%2BF2JK370yt5f2%3Dv6gOcOedgkpA%40mail.gmail.com)

4. **Memory context statistics get integer keys for shared hash** — Rahila Syed posts updated patches switching from string-based dshash keys to integer ProcNumber keys for better efficiency in the memory context statistics feature, addressing reviewer feedback about unnecessary initializations and path length limits. [link](https://www.postgresql.org/message-id/CAH2L28sC0Bo5nKzmzUaB4_bg1gVM%3DTSvD18MjkPQ2tkbjc0vjg%40mail.gmail.com)

5. **HOT logic debate centers on table AM abstraction** — Greg Burd clarifies his patch moving HeapDetermineColumnsInfo() to the executor is about separating heap-specific behavior from general "skip index updates" concepts that other table AMs might implement differently; identifies three subsystems (indexes, types, tables) that should influence update decisions.
