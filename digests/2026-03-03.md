# pgsql-hackers digest — Mar 3, 2026

1. **astreamer_lz4 output pointer advancement bug in decompressor** — Chao Li finds that astreamer_lz4_decompressor_content() advances next_out using the cumulative bytes_written instead of just the current iteration's out_size, effectively double-counting progress; the bug is hard to hit in practice because the default 1KB output buffer is typically filled in one or two LZ4F_decompress() iterations, but can be triggered by artificially limiting out_size. https://www.postgresql.org/message-id/0594CC79-1544-45DD-8AA4-26270DE777A7%40gmail.com

2. **Shutdown hang fix revised to call XLogSetAsyncXactLSN in ShutdownXLOG** — Anthonin Bonnefoy updates the FPI_FOR_HINT shutdown hang patch after Fujii Masao suggests calling XLogSetAsyncXactLSN() in ShutdownXLOG() instead of RecordTransactionAbort() to minimize backport risk, though the RecordTransactionAbort approach better handles backlogs of records from selects pruning many pages; adds optimization to skip spinlocks when XactLastRecEnd is 0. https://www.postgresql.org/message-id/CAO6_Xqp%2BADb6KZVWLMALu3xmwVUEO8S1EiCnp38mG6BrHrEnuA@mail.gmail.com

3. **pg_stat_replication.*_lag shows NULL when WalRcvForceReply triggers extra message** — Shinya Kato discovers that pg_stat_replication lag columns show NULL during active replication when the startup process calls WalRcvForceReply() after fast replay, causing walreceiver to send two consecutive messages with applyPtr == sentPtr, violating the assumption that the second such message must come from wal_receiver_status_interval; proposes tracking whether force_reply triggered the message. https://www.postgresql.org/message-id/CAHGQGwE%3DkyQ%2BYnGPn8zpZ959%2B3ywg8OR_Nu__uXxxuE0E%2BY_Zg@mail.gmail.com

4. **REPACK per-change memory context fixes attrs/isnull array leaks** — Antonin Houska addresses Mihail Nikalayev's memory leak findings by adding a per-change memory context (which he later realizes needs to be reset at the end of store_change()), adds rd_pkindex fallback logic to rebuild_relation_finish_concurrent(), and clarifies that ProcessRepackMessages() doesn't need SHM_MQ_DETACHED checks because RepackWorkerShutdown() sends error messages before detaching. https://www.postgresql.org/message-id/83637.1772472210@localhost

5. **Fix multixact Oldest*MXactId initialization comment inaccuracies** — Heikki Linnakangas fixes comments after Chao Li notes that PreparedXactOldestMemberMXactIdSlot() says "reserved for regular backends" when it should say "reserved for prepared transactions", and that the multixact.c comment claiming "Each is indexed by ProcNumber" is no longer accurate for OldestMemberMXactId prepared-xact entries which use (procno - FIRST_PREPARED_XACT_PROC_NUMBER). https://www.postgresql.org/message-id/c585168a-210a-4728-8e5e-8e9384126ccd%40iki.fi

6. **pg_dumpall --roles-only mutual exclusion checks could use helper function** — Nathan Bossart proposes adding a function to check arbitrary numbers of mutually exclusive options instead of maintaining a long list of individual checks, in response to Zsolt Parragi's review of the pg_dumpall --roles-only interaction patch. https://www.postgresql.org/message-id/aaYSFLaZL4Pb-DCd@nathan

7. **On-access VM setting needs targeted micro-benchmark for evaluation** — Melanie Plageman responds to Andres Freund's request for evaluation of on-access all-visible page marking frequency, noting that generic pgbench tests may not reliably demonstrate un-all-visibling patterns; also updates v35 to use explicit rel_read_only flag instead of passing vmbuffer or NULL to heap_page_prune_opt(). https://www.postgresql.org/message-id/CAAKRu_a1V7TUUYM7qO2c5Z-JyTKOsrryQBrk7Eu69ESzhqgd9w@mail.gmail.com

8. **NOT IN with NULL could constant-fold for EXPRKIND_QUAL contexts** — David Rowley observes that ScalarArrayOpExpr with !useOr, strict operator, and NULL array element can't currently constant-fold because the result differs (NULL vs false) depending on whether the left operand is found, but suggests passing "kind" into eval_const_expressions() since EXPRKIND_QUAL contexts don't distinguish NULL from false; reviews Ilia Evdokimov's v5 patch for NOT IN planning optimization. https://www.postgresql.org/message-id/CAApHDvphShGABn-3AoE36dTvGHW7gUpFSw0_ZZnH84wGCW3hHw@mail.gmail.com

9. **Pass-by-value Bitmapset using tagged pointers for immediate values** — Thomas Munro prototypes "immediate" Bitmapset values that skip allocation by tagging Node pointers with zero bit = 1 to indicate unboxed values, leaving 63 (or 31) bits to store the bitmap inline; immediate representation works for sets fitting in one word (except when 63/31 is the highest member since the tag eats a bit), with functions like bms_equal() checking if (bms_is_immediate(a)) return a == b. https://www.postgresql.org/message-id/CA%2BhUKGJdzw6tSTQrBZNe2f0tAr%2BGdttiSS7-b0aVwPDfi3uh3A@mail.gmail.com

10. **pg_upgrade fails when extension_control_path uses $libdir in module_pathname** — Jonathan Gonzalez V. reports that pg_upgrade from 18 to 19devel fails when using extension_control_path with extensions having $libdir/ hardcoded in module_pathname, because pg_upgrade uses the probin field from pg_proc to generate LOAD instructions without stripping the $libdir/ prefix; proposes applying the same technique used in the extension_control_path patch to remove $libdir/ when the extension name is required. https://www.postgresql.org/message-id/43b3691c673a8b9158f5a09f06eacc3c63e2c02d.camel%40gmail.com
